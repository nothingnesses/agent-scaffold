### `code-value-audit-deletion-experiment`: the deletion-experiment signal, gated behind an evidence gate (`Q-52`)

Add the DIRECT test of the falsifiable thesis to the code-value report (`code-value-audit-static`): the deletion experiment. Code earns its keep iff removing it causes an OBSERVABLE loss. Two granularities, both run in `checks`'s existing throwaway-worktree machinery (never a second isolation path): function/method granularity via `cargo-mutants` body-nulling (a surviving mutant means no test pins the body, the "pseudo-tested method" of Niedermayr et al.); and item granularity (remove or `#[cfg(any())]`-gate a `struct` / `enum` / `field` / `module`, then `cargo build` + `cargo test`) for kinds `cargo-mutants` does not target. This realizes the reserved `Kind::Mutation` variant (`src/checks.rs:94-95`, `src/checks.rs:671-672`), bounded by the already-parsed `budget` / `threshold` fields (`src/checks.rs:131-142`), scoped ONLY to the shortlist the cheap static signals flagged, never the whole crate.

DEFERRED behind an EVIDENCE GATE. It un-gates only once there is a measured count, from the `code-value-audit-static` report in practice, of cases where `clippy -D warnings` + rustc `dead_code` PASSED but the deletion experiment would have caught real dead code, above a small threshold. Until then the expensive, high-false-positive part stays on the shelf, because the compiler + clippy already cover the cheap case at zero cost and the incremental true-positive rate of the deletion experiment over them is unproven while its false-positive rate is structurally high (public/contract surface, `#[cfg]`-gated code, FFI, and error / defensive paths the test suite does not exercise; see `docs/plans/code-value-audit.explorations/Q-52-skeptic.md`). The debloating soundness numbers quantify the danger of an incomplete oracle (13-22% sound, up to 94% over-removal; `docs/plans/code-value-audit.explorations/Q-52-prior-art-survey.md`), which is why "nothing noticed" stays a candidate, never a proof, and the report never auto-deletes.

Sequencing note: the deletion experiment is structurally a class of mutation operators, so it must not ship as a second mechanism before the mutation module is piloted; building it here IS that pilot, scoped small. Judged against the plan principles: Minimal by default and Ground decisions in evidence hold it behind the gate; Prefer the cleaner long-term architecture over the smallest diff and Reproducible drive the reuse of `checks`'s isolated worktree rather than a parallel path. Decided item under `Q-52` (human, 2026-07-24); design record `docs/plans/code-value-audit.explorations/Q-52-multi-signal-design.md`. Do not build until the gate clears.
