### `code-value-audit-static`: the cheap static-only code-value report (`Q-52`)

Build the Tier-0 slice of the Q-52 code-value audit: an advisory report of code that may not be earning its keep, computed from ZERO/low-cost STATIC signals only, projected from a machine-readable intermediate (JSON) to a kept `docs/plans/<task>.code-value-report.md` (Structured data first, project for humans). Signals: rustc `dead_code` / `unused_*` warnings harvested from `cargo build --message-format=json` (free); `#[allow(dead_code)]` / `#[expect(dead_code)]` markers read as author-declared reasons, NOT candidates (Chesterton's Fence encoded in the source, e.g. `Check::budget` / `Check::threshold` at `src/checks.rs:135`, `src/checks.rs:140`); and `cargo-machete` for unused dependencies. No coverage, no traceability, no deletion experiment, no hotspot ranking in this step (those are Tier 1+ / the gated sibling `code-value-audit-deletion-experiment`).

Mandatory guardrails baked in before any candidate reaches a human (from the skeptic lens, `docs/plans/code-value-audit.explorations/Q-52-skeptic.md`): exclude the CLI / output / pack contract surface (this crate is a PURE BINARY, no `src/lib.rs` / `[lib]`, so there is no downstream Rust API; the contract to exclude is the subcommand / flag / output-format / emitted-pack surface, not arbitrary `pub` items); exclude `#[cfg(...)]`-gated and FFI (`#[no_mangle]` / `extern`) code (a static pass on one cfg is unreliable for these); and carry an explicit "not evidence of absence" caveat on every report ("nothing noticed" is necessary-not-sufficient and only relative to the named signal set, per `docs/plans/code-value-audit.explorations/Q-52-prior-art-survey.md` correction 3). The report is ADVISORY and never auto-deletes; a human decides each candidate and turns accepted deletions into a kickoff task, the same handoff the review entry mode already produces.

Honest scope note (the sharpest skeptic cut): `cargo clippy --all-targets -- -D warnings` (already required pre-commit) plus rustc `dead_code` already cover most of this cheap case at zero marginal cost, so this step's incremental value over the existing guards is modest; it is scheduled as the cheap, low-false-positive slice that also produces the kept, structured, human-projected report the bare lints do not, and it is the measurement surface for the sibling's evidence gate (counting cases where clippy passed but a deletion experiment would have caught real dead code). Judged against the plan principles: Minimal by default (cheap signals only, no engine we do not need), Ground decisions in evidence (per-candidate `file:line` evidence, no heuristic score), Structured data first, project for humans (JSON intermediate -> Markdown), and Prefer the cleaner long-term architecture over the smallest diff (one report, reused by the later deletion-experiment tier). Decided item under `Q-52` (human, 2026-07-24); design record `docs/plans/code-value-audit.explorations/Q-52-multi-signal-design.md`.
